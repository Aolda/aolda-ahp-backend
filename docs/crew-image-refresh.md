# 선택 크루 프로필 이미지 캐시 갱신

관리자 콘솔은 백엔드가 제공하므로 프런트엔드 저장소 변경 없이 적용한다.

## 동작

크루 관리에서 체크박스로 선택 → 선택 이미지 새로고침.
POST `/admin/crews/image-refresh`에 선택 UUID 목록을 보내면 HTTP 202와 작업 ID를 반환하고 즉시 서버 작업을 시작한다.
관리자 인증이 필요하며 한 번에 1~1,000명을 받는다. 보관된 크루나 잘못된 ID가 있으면 시작하지 않는다.

- 연결된 `primaryNotionPageId`를 새로 조회한다. 설정된 Notion Crew datasource 소속인지 검증한다.
- 일반 동기화와 동일하게 페이지 이미지 아이콘 우선, 없으면 페이지 본문의 첫 이미지(하위 블록 포함)를 사용한다.
- 오래된 signed URL을 재사용하지 않는다. Notion 요청은 10초 제한 및 제한된 429/서버 오류 재시도를 사용한다.
- 2명씩 처리하고, 파일은 content hash 이름으로 원자적으로 저장한다. 내용이 같으면 같은 URL, 바뀌면 새 URL이다.
- 성공 시 공개 이미지 URL/캐시 메타데이터/항목 완료 상태를 한 DB 트랜잭션에 기록한다.
- 실패, 이미지 없음, Notion 미연결은 기존 이미지를 유지한다. 이름·소개·학과·입학연도·공개 여부는 변경하지 않는다.
- `CrewSource.profileImageCacheUrl`은 일반 Notion 동기화가 덮어쓰지 않는 캐시 선택값이다. 공개 목록/상세/프로젝트 참여자는 이를 우선 사용한다.

## 진행률과 재시도

팝업은 실제 완료 항목 수/전체 수, 성공·실패·건너뜀 및 사람별 상태를 1.5초마다 조회한다.
닫으면 클라이언트 조회만 멈추며 서버 작업은 계속된다. 페이지 새로고침 후 ‘이미지 갱신 현황’으로 최근 작업을 다시 연다.
응답이 유실된 경우에도 최근 작업부터 확인한다. 활성 작업은 DB unique key로 하나만 허용한다. HTTP 409는 기존 작업 ID를 반환하고 UI는 그 작업을 표시한다.

서버는 15초마다 90초 lease를 연장한다. 갑작스러운 종료/DB 연결 상실로 만료된 작업은 다음 조회/시작 시 INTERRUPTED로 정리하고 미완료 항목을 실패로 표시한다. 완료된 이미지와 파일은 유지한다.
새 서버가 아직 살아 있는 이전 서버의 작업을 임의로 중단하지 않는다. 만료된 worker는 DB 쓰기 전 lease 검사에 실패한다.
실패한 대상을 다시 선택해 재실행한다. 이미지를 강제로 지우거나 Notion에 쓰는 기능은 아니다.

## 다운로드 제한

공개 HTTPS/443, 최대 5MB, 총 다운로드 10초, 최대 3회 리다이렉트. 매 hop에서 DNS를 확인하고 검증한 IPv4 주소에 연결을 고정한다.
사설망/loopback/metadata/예약 대역, 사용자정보 포함 URL, IPv6-only 호스트는 거부한다. PNG/JPEG/WEBP/GIF/AVIF signature를 검사하며 SVG/XML/HTML은 거부한다.
호환되지 않는 외부 이미지라면 Notion에 지원 형식 파일로 업로드한 뒤 재시도한다. 실패 응답/작업 로그에 signed URL이나 외부 오류 원문을 넣지 않는다.
기존 파일은 롤백과 참조 보존을 위해 삭제하지 않는다. 장기 저장공간 정리는 별도의 보존정책 결정이 필요하다.

## 검증

`npm run prisma:generate`, `npm run typecheck`, `npm run build`, `npm run crew:images:test`, `npm run crew:academic:test`.
`npm run crew:images:integration`은 localhost:55439의 `ahp_admin_features_test?schema=image_test`에서만 실행된다.
실제 PostgreSQL + 합성 Notion/파일 저장 응답으로 선택 범위, 부분 실패, 진행률, 활성 작업 중복 차단, lease 만료, 재시도, 일반 동기화 이후 공개 캐시 유지, 관리자 값 보존을 검증한다.
실제 Notion/운영 이미지로 검증하는 것은 승인·병합 이후 운영 적용 단계에서 한다.

## 운영 적용/롤백 (PR 승인·병합 후에만)

1. AOLDA_BETA_nate2402 기존 ahp 네임스페이스만 변경한다. 실제 승인 SHA/diff를 확인하고 현재 이미지/매니페스트/DB/PVC 이미지 디렉터리를 백업한다.
2. 실제 스키마와 migration 이력을 확인한다. 기존 운영의 db push 이력을 임의로 정리하거나 `migrate deploy`를 무작정 실행하지 않는다.
3. `20260827120000_crew_image_refresh/migration.sql`의 nullable 캐시 URL 컬럼 1개, 작업 테이블 2개 및 인덱스만 트랜잭션으로 추가한다. 존재하면 구조를 확인하고 건너뛴다.
4. `PROFILE_IMAGE_STORAGE_DIR`가 영속 볼륨이고 앱 사용자에게 쓰기 가능한지, `PROFILE_IMAGE_PUBLIC_BASE_URL`이 homepage의 기존 /api·이미지 프록시 경로와 호환되는지 확인한다. 기존 Secret 전체를 덮어쓰지 않는다.
5. 새 backend 이미지 배포 후 관리자 인증, 한두 명 선택 갱신, 진행률/결과, 홈페이지·크루북·상세의 이미지 응답을 검증한다. 일반 Crew 동기화 뒤 캐시 유지도 확인한다.
6. 실패 시 앱 이미지부터 롤백한다. 추가 컬럼/테이블/파일은 남긴다. 구버전 `prisma db push`로 새 스키마를 삭제하지 않는다. 롤백 중 일반 동기화는 새 캐시 선택을 무시할 수 있으므로 중지한다.

이 PR은 운영을 변경하지 않으며 자동 승인/병합을 수행하지 않는다.
